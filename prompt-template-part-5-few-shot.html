Prompt Template, Part 5

Show, do not tell: teach with examples

Read after Part 2. The template from Part 1 tells the AI what you want. Examples show it what you want. A few good examples often beat a long description, because the AI copies the pattern it sees.

The idea

What few-shot prompting is

Few-shot prompting means giving the AI examples of the job before you ask it to do the job. Each example has an input and the output you want for it. The AI reads the pattern across your examples, then applies it to your new input.

The one rule: the AI copies what your examples do, including their format, their tone, and their mistakes. Good examples teach a good pattern. Sloppy examples teach a sloppy pattern.

Three ways to ask

  • Zero-shot: no examples at all. You describe the job and hope the description is enough. Works for simple, familiar jobs.
  • One-shot: one example. Enough when the job is clear and the format is simple.
  • Few-shot: two to five examples. The usual choice when the format matters, the tone matters, or the job is unusual.

The examples are part of the prompt, not separate from it. They sit in the Context of your template, right before the new input you want handled.

How many

How many examples do you need

Start with one. Test it on your real input. If the output comes out right, stop. If it misses, add a second example that shows the case it got wrong. Two to five examples cover most jobs.

  • One example is enough when the format is simple: a label, a short rewrite, a one line answer.
  • Two or three examples are the sweet spot for most jobs: they show the pattern and a little variety.
  • Four or five examples help when the job has tricky cases, like messages that look similar but belong in different groups.
  • More than five rarely helps. Long example lists eat up the context window, cost more, and can confuse the model with too much to copy at once.

Add examples only to fix a specific miss. If the output is wrong about tone, add an example with the right tone. If it is wrong about format, add an example in the right format.

Quality

What makes a good example set

  • Same format, every time. If the first example is "Input: ... Output: ...", every example uses the same two labels, in the same order.
  • Varied content. The examples should cover the range you expect: short and long inputs, easy and tricky cases, not three copies of the same easy case.
  • Correct answers. Check every example before you send it. A wrong answer in an example is a lesson the AI will learn.
  • Clear labels. Mark the input and the output the same way in every example, so the model can tell them apart.
  • Real inputs. Use the kind of input you will actually send, not made up textbook cases, when you can.

Before you trust it

Few-shot checklist, for every prompt

  • Did I show at least one example before asking for the real job?
  • Do all my examples use the same format, with the same labels?
  • Do the examples cover the variety I expect, not just one easy case?
  • Did I label the input and the output in every example?
  • Did I check every example for mistakes before sending it?
  • Did I stop adding examples once the output came out right?

Remember: examples teach the pattern, for good and for bad. A small set of correct, varied examples beats a long list of sloppy ones.

Common failure modes

  • “All my examples look alike”: the model learns only one shape. Fix: vary the content while keeping the format.
  • “My examples disagree”: two examples show different formats for the same job. Fix: one format, every time.
  • “Too many examples”: a long list eats the context window and muddies the pattern. Fix: start with one, add only to fix a miss.
  • “The model copied my mistake”: an example had a typo or a wrong answer, and the model repeated it. Fix: check every example before you send it.
  • “Examples with no labels”: the model cannot tell the input from the output. Fix: label each part the same way, every time.

Reference

Glossary: few-shot terms

Short, plain definitions for the new terms used on this page. The Part 2 glossary covers Context, Role, Goal, and Constraints.

Few-shot
Prompting with two to five examples of the job, so the AI copies the pattern they show.
Zero-shot
Prompting with no examples at all, only a description of the job.
One-shot
Prompting with a single example of the job.
Example
One input paired with the output you want for it, shown to the AI before the real job.
Pattern
The shape the examples share: their format, order, tone, and level of detail.
Format
The exact shape of an output: its labels, line breaks, length, and order.
Label
A short marker that names a part of an example, such as Input, Output, Q, or A.
Input
The material you give the AI to work on, such as a message, a note, or a product line.
Output
What the AI gives back, such as a label, a rewrite, or a set of flashcards.
Consistency
Every example using the same format and labels, so the pattern is easy to copy.
Edge case
An unusual input that does not fit the easy pattern, such as a message about a school bill.
Context window
How much text the AI can hold in mind at once, including your examples and its answer.
